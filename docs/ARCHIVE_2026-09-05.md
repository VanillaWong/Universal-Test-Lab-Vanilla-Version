### A. AIM-120 挂载"2 个 2 发"（bug，已修，commit f92db48 数据部分）
- 现象：F-16XL-1 第 13 挂架（slot 7 / order 13）AMRAAM 应显示 2 发与 4 发两档，UTL 显示两行都像 2 发
- 根因：游戏原生把同一挂点方案拆多个 blk——`aim_120a` 方案 = 2× `us_aim_120a.blk` + 2× `us_aim_120a_default.blk`（共 4 枚，图标 `_x4`）。Build-Catalog.ps1 弹数累加要求 **trigger 与 blk 完全一致** 才计入 → 混装的 default 弹被丢 → 算成 2
- 修复（Build-Catalog.ps1 Phase 2，弹数累加段）：比较**弹种基名**（`GetFileName` 去 `_default` 后缀）相同即累加；真混装异型弹（不同基名）仍按首个计，保持原行为。注释为中文，位于累加循环上方
- 数据验证：donor_weapons 该行 `aim_120a_default=2 | aim_120a=4` ✓

- 正确三连：`Build-Catalog.ps1`（或 `Update-Data.ps1 -SkipExtract -SkipCompile`）→ `node tools/tsv2json.js` → `compile.bat`
- 时间戳证据法：`data/*.tsv` 与 `data/*.json` 的 mtime 不一致 = 缺跑 tsv2json

### C. core `--selftest` 崩（玩家"开不了 UTL"主因，已修，commit 3fc50c9）
- selftest 是什么：命令行自检开关（`--selftest` / `--uiselftest` / `--selftest-config` / `--selftest-session`），正常双击 GUI 不跑；`Build.ps1 -SelfTest` 发布链会跑前两个。核心 = 模拟生成完整任务后对结果文本做"该有/不该有"断言
- 根因：Ground rearm override 默认关（上轮）改了生成路径与 selftest 断言，但 selftest 8044 行仍用**旧的无参重载** `AccelerateRangeRecovery(groundMission)`（永远注入 Fast Rearm Policy）→ 与"默认关 = 不含 rearm 策略块"断言矛盾 → 自检必挂
- 修复（原 UniversalTestLab.cs → 现 `UniversalTestLab.Program.cs` 的 selftest 段 + BlkTools）：
  - 调用改为 4 参显式传 `rearmSeconds: null`（对齐真实生成路径的 `RearmOverride ? (double?)RearmSeconds : null`）
  - 补正向断言：override 开（rearmSeconds=1.0）时必须含 `UTL Fast Rearm Policy` + `rearmTimeOnField:r=1`
  - `AccelerateRangeRecovery` 语义（勿再改）：`rearmSeconds` 为 `double?`，null → 不注入 rearm 策略块（保留 respawn 加速 / APS 恢复）；combined 模板无 `triggers` 块会提前 return（之前 7959 行"侥幸通过"的原因）

### D. UI `--uiselftest` 崩（两个独立 bug，已修，commit 3fc50c9）
- bug 1：自检假设"窗口默认选中飞机、挂架面板有内容"，但窗口恢复上次 session——**玩家常用坦克**（如 `germ_machinegun_mg_08`）→ 地面状态 → pylonPanel/weaponList 空 → layout 断言挂 → 任何坦克党机器上 Build.ps1 -SelfTest 都崩

### E. 上帝类 partial 拆分（零行为变化，commit 3c88915）
- 动机：ModernShell.cs 8710 行 + UniversalTestLab.cs 8346 行；跨层契约（生成逻辑↔UI↔selftest↔config）靠人肉同步，8000+ 行让"找全牵涉点"极难 → 本次三类 bug（selftest 未同步/依赖 session/XAML 哨兵）都是放大器效应
- 手法：纯文件搬移 + `partial` 修饰符；成员逐字节未动；拆完 **编译 + 三自检全绿** 才算过
- 拆分工具链（自建，可复用）：node 词法扫描器（跳过字符串/注释/verbatim 的括号配对）求类边界 → 按"行区间组"搬移 + 源文件删除行 + 新文件 `namespace` 包裹
- **partial 拆分的坑（下次直接用）**：
  - 每个 partial 段文件都必须**括号自洽**（类开 `{` 类闭 `}` 在段内成对）——切点必须落在成员边界（方法声明行）
  - 类声明只放一个段，其余段用 `internal sealed partial class X` 无基类包装
  - 段尾若含原类闭行会双闭（内容自带 `}` 时别再 wrap）
  - 源文件若保留首段，类闭要加在**段尾**而非文件尾（否则后续类被吞进类体 → "type not found"）
